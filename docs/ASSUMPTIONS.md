# Assumptions & Defaults

> [!NOTE]
> When a requirement is ambiguous, KnowFlow picks the **safest simple option** and documents it here.
> Each assumption is revisitable — file an ADR to override any row.

| # | Area | Question | Default Assumption | Rationale |
|---|------|----------|--------------------|-----------|
| A-01 | Documents | Which file types are supported for upload and ingestion? | **PDF only in v1.** Office formats (DOCX, XLSX, PPTX) planned for v2 behind a feature flag. | PDFBox gives page-aware extraction out of the box; Office parsing (Apache POI) adds complexity, different page semantics, and macro risks. Ship the common case first. |
| A-02 | Documents | What is the maximum upload size per file? | **50 MB per file.** Enforced at both the reverse-proxy (if present) and Spring `MultipartConfigElement`. | Covers 99 %+ of enterprise PDFs. Larger files (engineering drawings, scanned archives) require a separate bulk-import workflow. |
| A-03 | Classification | How many classification levels exist and what are they? | **Four levels:** `PUBLIC`, `INTERNAL`, `CONFIDENTIAL`, `RESTRICTED`. Stored as a `VARCHAR` status enum in the `documents` table. | Mirrors common enterprise DLP tiers (e.g., ISO 27001 Annex A). Kept as an open enum so a Flyway migration can add levels later. |
| A-04 | Classification | What does `PUBLIC` mean? | Visible to **all authenticated users in the same organisation**. Not visible to anonymous/unauthenticated users. | "Public" in an enterprise context still requires login. External sharing is out of scope for v1. |
| A-05 | Classification | What does `INTERNAL` mean? | Visible to **users in the same department** as the document's `department_id`, plus any user with an **explicit permission** (`VIEW`, `EDIT`, or `MANAGE`). | Balances discoverability within a team with need-to-know for outsiders. |
| A-06 | Classification | What does `CONFIDENTIAL` mean? | Visible **only** to users who hold an **explicit `VIEW`, `EDIT`, or `MANAGE` permission** on the document, plus the document owner. | Prevents accidental department-wide exposure of sensitive material. |
| A-07 | Classification | What does `RESTRICTED` mean? | Visible **only** to users with an **explicit `MANAGE` permission** on the document, plus users with the `ADMIN` role. | Highest sensitivity tier. Even `VIEW` grants are insufficient — only `MANAGE` + `ADMIN` can access. |
| A-08 | Documents | Is there a hard limit on versions per document? | **No hard limit.** A soft warning is logged (and surfaced in the UI) when a document exceeds **100 versions**. | Hard limits break legitimate revision-heavy documents; the soft warning alerts admins to potential abuse or misconfiguration. |
| A-09 | Ingestion | What is the target chunk size for document splitting? | **~512 tokens** with **~64 token overlap** between consecutive chunks. | 512 tokens fits well within typical embedding model context windows (8 K tokens) and retrieval top-k budgets. 64-token overlap preserves sentence boundaries. |
| A-10 | Ingestion | What embedding dimensionality is used? | **1536 dimensions** (matches `text-embedding-ada-002` / `text-embedding-3-small`). Configurable via `knowflow.embedding.dimensions`, **validated at application startup**. | 1536 is the most widely supported default. Startup validation prevents silent dimension mismatches that corrupt the HNSW index. |
| A-11 | Ingestion | How many ingestion jobs can run concurrently? | **4 concurrent jobs** (configurable via `knowflow.ingestion.max-concurrent`). | Limits CPU/memory pressure on the monolith. Tunable per deployment size. |
| A-12 | Auth | What is the JWT access token lifetime? | **15 minutes.** | Short-lived tokens limit the blast radius of a stolen token while keeping UX acceptable with silent refresh. |
| A-13 | Auth | What is the JWT refresh token lifetime? | **7 days.** Stored as a hashed value in `refresh_tokens`. Rotation on use (old token revoked, new token issued). | Balances convenience (users stay logged in for a work week) with security (rotation detects token reuse). |
| A-14 | Auth | What login rate limiting is applied? | **5 failed attempts per email address per 15-minute window.** Returns `429 Too Many Requests` after the limit. | Prevents credential stuffing while allowing genuine typos. Window-based (not permanent lockout) to avoid denial-of-service on legitimate accounts. |
| A-15 | Copilot | How many copilot questions can a user ask per hour? | **30 questions per user per hour.** Tracked server-side per `SecurityContext` principal. | Controls LLM API cost. 30/hour ≈ one question every 2 minutes, generous for normal use. |
| A-16 | Copilot | How many tool calls can the model make per single copilot request? | **5 tool calls maximum.** The orchestrator hard-stops after 5 invocations regardless of model intent. | Prevents infinite tool-call loops and bounds latency/cost per request. |
| A-17 | Search / Copilot | How many passages are retrieved per copilot question? | **10 passages maximum** (top-k = 10 after re-ranking and access filtering). | Balances recall with context window budget. Authorization filtering may reduce the effective count below 10. |
| A-18 | Copilot | How many context tokens are sent to the model? | **4 096 tokens maximum** for retrieved context (system prompt and user message are additional). | Keeps total prompt under 8 K tokens for cost efficiency; leaves room for model reasoning. |
| A-19 | Copilot | How long are conversations retained? | **1 year** from last message, then eligible for automated purge. Configurable via `knowflow.copilot.retention-days=365`. | Retains context for audit and user reference without unbounded storage growth. |
| A-20 | Audit | How long are audit logs retained? | **2 years** from creation. Append-only; no application-layer UPDATE or DELETE. Purge is a scheduled admin job. | Meets typical enterprise compliance requirements (SOX, ISO 27001). |
| A-21 | Documents | What happens when a document is archived? | Archived documents are **excluded from search results and copilot retrieval**. Chunks and embeddings are **retained** so that existing citations remain resolvable. An archived document can be **restored** by its owner or any `ADMIN`. | Soft-delete preserves citation integrity. Full physical deletion is a separate admin action (not in v1). |
| A-22 | Approvals | Can a new version be uploaded while an earlier version is under review? | **Yes.** A new upload creates a new `DRAFT` version candidate. The in-progress approval on the older version is **not affected** — it proceeds independently. | Avoids blocking authors. The approval process is version-specific, not document-wide. |
| A-23 | Approvals | Can a user approve their own document? | **No. Self-approval is blocked for all roles**, including `ADMIN`. The API returns `403 Forbidden` if `submittedBy == currentUser`. | Four-eyes principle. No role should bypass segregation of duties. |
| A-24 | Approvals | What happens to the document when an approval is granted? | Document status is set to `APPROVED` and `current_version_id` is updated to point to the approved version. | Makes the approved version the "live" version visible in search and copilot. |
| A-25 | Notifications | Which notification channels are supported? | **In-app only in v1.** The `NotificationSender` interface is designed for pluggable channels; an email adapter is planned for v2. | Keeps v1 simple. The interface boundary ensures email/Slack/Teams can be added without refactoring. |
| A-26 | Identity | What identity provider is used? | **Local JWT authentication in v1.** The `identity` module exposes an OIDC-ready interface (`IdentityProvider`) so that SSO (Okta, Azure AD, Keycloak) can be plugged in via configuration. | Most enterprise pilots start with local auth; OIDC integration comes during IT onboarding. |
| A-27 | Deployment | What is the deployment target? | **Docker Compose in v1.** No Kubernetes, no Helm charts. A single `docker-compose.yml` runs `app`, `postgres`, and an optional `pgadmin`. | Matches the "modular monolith" architecture. K8s adds operational complexity not justified at v1 scale. |
| A-28 | Pagination | What are the default and maximum page sizes? | **Default: 20 items.** **Maximum: 100 items.** Any `size > 100` is clamped to 100 server-side. | Prevents clients from requesting unbounded result sets. 20 is a comfortable UI default. |
| A-29 | Search | Does keyword search work when the AI provider is down? | **Yes.** Keyword search uses PostgreSQL `tsvector` full-text search and has **zero dependency** on the embedding/LLM services. | Architecture rule #7: non-AI features must work with the AI provider fully down. |
| A-30 | Documents | What is the optimistic locking strategy? | A `version` column (integer, not null, default 0) on `documents`, `approval_requests`, and `tasks`. JPA `@Version` annotation. `409 Conflict` on stale writes. | Prevents lost updates in concurrent editing scenarios without pessimistic locking overhead. |
| A-31 | Copilot | Is retrieved document text treated as trusted? | **No.** All retrieved text is **UNTRUSTED DATA**. It is rendered as content, never parsed as instructions, and cannot grant permissions or trigger tool calls. | Architecture rule #8. Mitigates prompt injection via uploaded documents. |
| A-32 | Security | Where does the acting user identity come from? | **Always from the authenticated `SecurityContext`** — never from request bodies, path parameters, or model output. | Architecture rule #9. Prevents privilege escalation via parameter tampering. |
| A-33 | Ingestion | How is PDF extraction performed safely? | **Apache PDFBox 3.0.3** per page. Encrypted or password-protected PDFs fail immediately with permanent error `PDF_ENCRYPTED`. | Defensive extraction prevents worker hang. |
| A-34 | Ingestion | What are the chunking parameters? | **~500 tokens target budget (~2000 chars)** with a **50-token sliding overlap (~200 chars)** respecting paragraph boundaries. | Token-aware chunking optimized for subsequent semantic retrieval and citation page mapping. |
| A-35 | Ingestion | How are concurrent workers coordinated? | **Database lease with heartbeat**. Workers atomically claim candidates with `tryClaimLease` and renew leases. Expired leases are reclaimed on worker crash. | Bounded concurrency without external distributed lock managers. |
| A-36 | Ingestion | How is zero-downtime reprocessing handled? | **Shadow pipeline versioning**. Chunks are saved under the new pipeline version (e.g. `v2`). The active version pointer switches atomically upon completion. | Zero search disruption during pipeline upgrades. |
